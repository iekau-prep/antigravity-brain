- Scope：SNS流入→個人診断→結果理解→状況別CTA→パートナータイプ選択／次Module→LINE任意保存。

## 1｜体験の目的と位置付け

家買う予備校のSNS流入を受け止める入口。目標は「個人タイプを見せびらかす」ことではなく、**約1分で自分の住宅購入における判断傾向や次の整理ポイントが見え、他人にも診断体験を勧めたくなること**。

- 個人診断：自分の判断傾向、強み・注意点、次に整理すべきことを理解する。
- 二人の家選び相性：2タイプの共通点・違い・話し合うヒントを確認する。優劣判定、相性スコア、購買適性の判定はしない。
- SNS展開：個人診断は「1分で家探しの考え方が整理された」という実用体験、夫婦・パートナー向けは「二人の違いが見える」という関心から広める。

## 2｜理想の主導線

1. SNSなどからアクセス。短い説明で診断開始の価値が分かる。
2. 補助質問：「家を買うとしたら誰と相談して決めますか？」（自分中心／パートナー／家族など／まだ決めていない）。**タイプの判定とは分離**し、結果画面の主CTAを調整するために使う。選択肢・時点は後続UI検証で最終化。
3. 10問の診断。約60秒で完了することを目標とし、1問ずつ、進捗表示と修正可能な回答UI。正式な回答スケール・スコアは既存Product Authority照合が必要。
4. 個人結果：8タイプの本人結果、家探しで表れやすい判断傾向、具体例、次に整理すべきことをコンパクトに提示。
5. **個人の診断カード直下に「SNSで共有」**を補助アクションとして置く。結果の公開は本人操作による。
6. パートナーと相談するユーザーには「二人の家選び相性を見る」をメインCTA。単独で進めるユーザーには次のModuleをメインCTA（初期候補はrent_vs_buy、状況に応じた将来拡張可）。その他の回答にも自然な出口を設ける。
7. 「LINEで診断結果を保存」はサブCTA。診断・相性比較・SNS共有にLINE連携を要求しない。

## 3｜二人の家選び相性：最小・自由な導線

- メインCTAで相性画面へ。本人のタイプは表示済み。
- 「パートナーのタイプを選ぶ」をタップすると、**8タイプのカード（スマホでは2列×4段）**が展開。
- 相手のタイプは自由に選択でき、**何度でも選び直し・比較し直し可能**。
- 「予想した結果／本人診断済み」の区別、診断済み証明、比較同意フロー、二人のアカウント・匿名ID紐づけはこの軽量相性体験に要求しない。
- 相手が未診断なら、**通常のtype_diagnosisリンク**を送る補助導線を置く。専用招待リンクは必要ない。
- 同じ組み合わせから共通点／違い／話し合うヒントを表示。8×8の組み合わせを想定するが、実際の生成規則・正式な説明文は既存Product Authorityに照合して確定する。
- 「パートナーとの比較」はユーザーが選択したタイプに基づく参考資料。相手本人の性格・同意・診断実施をシステムが証明するものとして表現しない。
- SNS公開用に相手の個別詳細・識別情報を載せない。共有用カードは非個人情報の説明に限定し、必要なら同意要件を別途設計する。

## 4｜CTA階層

| 表示場面 | 主CTA | 補助CTA |
| --- | --- | --- |
| 個人結果（パートナーと進める） | 二人の家選び相性を見る | 診断カード直下でSNS共有／LINE保存 |
| 個人結果（主に自分で進める） | 次のModuleへ | 診断カード直下でSNS共有／LINE保存 |
| 相手タイプ選択 | この組み合わせを見る | 通常の診断リンクを送る |
| 二人の相性結果 | 住宅購入の次の整理へ | 相手のタイプを変更／通常の診断リンクを送る／共有・保存 |

**1画面で主役となる行動は1つ。** SNS共有はカード付近に配置するが大きな主CTAにはしない。LINEは任意。

## 5｜モバイルUIの基準

- Primary：390×844、モバイルChrome。タップ領域・進捗・選択状態・戻る操作・キーボード・小画面の縦スクロールを考慮。
- 結果はカード→カード直下のSNS共有→具体的な傾向→状況別メインCTA→LINE補助の順。
- パートナータイプ選択は初期非展開、開くと2列×4段のカード。読みやすい名称と明確な選択状態。
- 選択変更だけでは外部連携・DB書込みを行わない。比較もログイン不要の読み取り体験として実現する。
- Web共有メニューの挙動には端末差があるため、カード画像保存／共有リンクコピーを代替手段にする。SNSアプリへの直接投稿は保証しない。
- LINEや別タブに移った後の戻りやすさを考慮する。

## 6｜境界・非目標

- タイプ診断は判断傾向の整理であり、物件の推奨・ランキング・借入判断・購入適性の断定はしない。
- 「相性」は住宅購入における二人の違いを考える入口。よい／悪い、点数、優劣の評価はしない。
- **MVP相性比較にペア招待ID、アカウント紐づけ、本人診断確認、LINE連携は不要。**
- 将来の「パートナー用限定アクセス」は別機能候補（閲覧＋自分の診断結果のみ編集可能等）。本Blueprintでは実装対象に含めない。
- 追加のDB・認証・外部通知基盤を、相性診断のために推測で作らない。
