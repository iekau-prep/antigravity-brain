# Design Formation Knowledge

## Purpose

Design Formation Knowledge（DFK）は、Current SoTのみでは再構成できない横断的なDesign Formation Knowledgeを保持する、`brain/`直下の独立領域である。

`brain/design/`が扱うUX・UI・体験設計の責務とは分離する。

## 対象

- 問題構造と分離の経緯
- Product Owner Decisionに接続するFormation Knowledge
- Close / ReducedおよびRemaining Gap
- Repository読解の変化
- Current BoundaryへのTraceability

## 非対象

DFKは、以下の代替ではない。

- Current SoT
- Decision History
- Current State
- Record
- Maturity
- Observation
- Transfer Information
- 工程、Implementation、Repository反映の進行記録

Repository Current Factと、Formation Input由来のProcess・因果は区別して扱う。Formation KnowledgeをCurrent SoTまたはRepository Factへ自動昇格させない。

## 既存ResponsibilityとのBoundary

DFKは既存のSystem設計、Operation進行、Maturity管理を置き換えない。案件時に必要な横断的Knowledgeを参照する領域であり、Owner、更新Lifecycle、Trigger、必読条件、詳細Loading Ruleはここで定めない。
